# Detection Rule Sync Action

> **⚠️ Beta Feature**: This action uses scanner-cli, which is currently in beta. See [Scanner.dev Beta Features](https://docs.scanner.dev/scanner/using-scanner/beta-features) for more information.

A GitHub Action that syncs an entire detection-rules repository to Scanner using `scanner-cli sync-git-repo`. The action zips the checked-out working tree (via `git ls-files`) and uploads it to a push sync source on Scanner, which then validates, tests, and materializes the rules — including deleting rules whose YAML has been removed from the repo.

## Usage

```yaml
name: Sync Detection Rules
on:
  push:
    branches: [main]

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: scanner-inc/sync-detection-rules@v0.1.0
        with:
          scanner_api_url: "${{ vars.SCANNER_API_URL }}"
          scanner_api_key: "${{ secrets.SCANNER_API_KEY }}"
          push_key: "${{ vars.SCANNER_PUSH_KEY }}"
```

## Inputs

| Input             | Description                                                                                                  | Required | Default |
| ----------------- | ------------------------------------------------------------------------------------------------------------ | -------- | ------- |
| `scanner_api_url` | The API URL of your Scanner instance                                                                         | Yes      | -       |
| `scanner_api_key` | Scanner API key                                                                                              | Yes      | -       |
| `push_key`        | Push key identifying the target push sync source on Scanner (Settings > Detection Rule Sync)                 | Yes      | -       |
| `path`            | Path inside the checkout to sync. `scanner-cli` resolves the enclosing git root and uploads the entire tree. | No       | `.`     |

See the [Scanner.dev CLI documentation](https://docs.scanner.dev/scanner/using-scanner-complete-feature-reference/beta-features/detection-rules-as-code/cli#sync-an-entire-repository-sync-git-repo) for details on obtaining your API URL, API key, and push key.

## How it works

The action installs the scanner-cli tool and runs `scanner-cli sync-git-repo --push-key <push_key>` against the checked-out repository. The current branch and commit SHA (with `+dirty` suffix if the working tree has uncommitted changes) are derived from the repo and uploaded alongside the zip.

The action runs `scanner-cli` with `--json` and reads the structured response. If any rule in the upload fails validation or its tests fail, the server rejects the whole upload, and each per-file failure is surfaced as a GitHub annotation on the rule's YAML file. Per-rule warnings are surfaced the same way.

## Development

This repo uses Yarn 4 (managed via Corepack).

To prepare a release:

1. Install dependencies: `yarn install`
2. Build the bundled distribution: `yarn build`
3. Commit the `dist/` folder: `git add dist && git commit -m "Build dist"`
4. Tag the release: `git tag v{$VERSION} && git push --tags`

The bundled `dist/index.js` contains all dependencies, so users don't need to install anything.

### Regenerating the schema bundle

`gen/sync_git_repo_result.ts` is an autogenerated bundle of TypeScript types for the JSON shape that `scanner-cli sync-git-repo --json` emits. **You only need to regenerate it if you've changed that schema upstream** in `scanner-inc/scanner-cli`. The committed bundle is what builds use, so most contributors can ignore this section.

To regenerate, install [`gh`](https://cli.github.com/) and authenticate it (`gh auth login`), then:

```bash
yarn gen_schema
```

The script downloads the latest schema from `scanner-inc/scanner-cli` and runs `json-schema-to-typescript` locally to produce the bundle. Override the source ref via `SCANNER_CLI_REF` if you need to pin to a non-default branch.
